# ResQNet simulation benchmarks

Generated by `BenchmarkSuite`. Reproduce with:

```
mvn -q -pl packages/mesh-simulator -am package -DskipTests
java -cp packages/mesh-simulator/target/classes:packages/mesh-core/target/classes \
  dev.resqnet.mesh.simulator.benchmark.BenchmarkSuite --seed 42
```

**These are simulation results, not field measurements.** They describe the
routing engine under a modelled radio. Nothing here is a claim about
Nearby Connections, real Wi-Fi Direct range or real battery life.

Host: 8 CPUs, 21.0.7+8-LTS-245, JVM max heap -Xmx3g.
Sweep wall time: 2472899 ms.

## Reading these honestly

- Latency is simulated time, advancing a manual clock at a fixed step.
  It does not include radio time, OS scheduling or any sleep.
- Amplification is forwards divided by originated. Flood routing
  grows it with mesh size by design; the two-cluster topology is the
  interesting row because a partition has to be routed around or not at all.
- Heap delta is noisy at small sizes and only meaningful as a trend.
- Per-node behaviour is identical across every seed; the seeds vary
  loss and churn, not the code path.
