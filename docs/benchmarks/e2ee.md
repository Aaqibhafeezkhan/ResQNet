# Directed-message E2EE overhead

Generated by `E2eeBenchmark` on the host JVM. These are microbenchmark numbers
for the HPKE path the router calls, **not** a radio or handset measurement.
Android Keystore signing, SQLite, Nearby Connections and battery cost are not
included.

Host: Mac OS X, Java 21.0.7. Warmup: 1,000 round trips per size; measured:
5,000 per size. Two consecutive runs agreed within 3%.

| Plaintext | Encrypted payload | Wire overhead | Encrypt | Decrypt |
|---:|---:|---:|---:|---:|
| 64 B | 154 B | 90 B | 0.283 ms | 0.145 ms |
| 256 B | 346 B | 90 B | 0.285 ms | 0.144 ms |
| 4,096 B | 4,186 B | 90 B | 0.281 ms | 0.143 ms |

The overhead is fixed at 90 bytes: a 42-byte `ProtectedPayload` header and 48
bytes of HPKE encapsulation plus AES-GCM tag. Encryption and decryption cost is
dominated by X25519 and is effectively flat across these payload sizes. At one
message every few seconds this is negligible next to the radio and the existing
P-256 envelope signature.

Reproduce:

```bash
mvn -q -N install
mvn -q -pl packages/mesh-core install -DskipTests
mvn -q -pl packages/mesh-simulator -am -DskipTests package
mvn -q -pl packages/mesh-simulator dependency:build-classpath \
  -Dmdep.outputFile=/tmp/resqnet-cp.txt
java -cp "packages/mesh-simulator/target/classes:packages/mesh-core/target/classes:$(cat /tmp/resqnet-cp.txt)" \
  dev.resqnet.mesh.simulator.benchmark.E2eeBenchmark
```

The 90-byte overhead reduces the cleartext budget per envelope rather than
increasing the frame size: `ProtectedPayload.MAX_PLAINTEXT_BYTES` is derived from
`MessageEnvelope.MAX_PAYLOAD_BYTES` minus the protected header and HPKE
authentication overhead.
